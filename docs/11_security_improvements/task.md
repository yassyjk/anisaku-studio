# タスク: セキュリティリスクの改善

現状のコードベースに存在するセキュリティリスクのうち、優先度の高い3項目について改善を行います。

## 背景

現状のコードはプロトタイプとしての利便性を優先しており、セキュリティ設定が緩和されています。本番運用を見据え、脆弱性を塞ぐための対策を講じます。

## 改善対象項目

1. **Originチェックの厳格化 (CORS/WebSocket)** [x]
    - 現状: `*` および `CheckOrigin: true` で全許可されている。
    - リスク: クロスサイト・ウェブソケット・ヒジャック (CSWSH) 等の攻撃。
    - 対策: 許可するドメインを環境変数等で指定可能にし、それ以外を拒否する。

2. **入力値の検証 (入力検証)** [x]
    - 現状: プレイヤー名やIDの長さ制限、無効な文字のチェックがない。
    - リスク: 表示崩れ、スクリプト注入、意図しない挙動。
    - 対策: バックエンドとフロントエンドの両方で文字数制限（例: 名前20文字以内）と型・形式チェックを実装する。

3. **リソース制限 (DoS対策)** [x]
    - 現状: ルーム作成数やメッセージサイズに制限がない。
    - リスク: 悪意のある大量リクエストによるメモリ枯渇やサービス停止。
    - 対策: サーバー全体での最大ルーム数制限、WebSocketのメッセージサイズ制限（ReadBufferSize等）を設定する。

## 目標

- 外部からの不正な通信を遮断する。
- 不正なデータによるシステム破壊や表示不具合を防止する。
- サーバーリソースを保護し、安定したサービス提供を可能にする。
