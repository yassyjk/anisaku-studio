# 実装計画

## バックエンド

`backend/handlers/websocket.go` の `GameState` と `processLogic` をゲーム固有の所有点と手番段階に拡張する。カード山札を要素ごとに16枚生成し、`take_card` と `resolve_turn` をプレイヤーID・手番段階に基づいて処理する。作品公開時はタグごとの出現数を集計し、同一タグ2/3/4枚以上をそれぞれ2/5/10点に変換する。状態配信時は要求者以外の手札をマスクする。

## フロントエンド

SolidJSの既存画面でカード取得、4要素選択、タイトル入力、公開または捨て札を操作可能にする。コイン、作品一覧、終了後ランキングを表示し、トップ/ロビーへ戻るボタンを用意する。追加ライブラリは不要で、既存のSolidJSとWebSocket/HTTP fallbackを利用する。

## ドキュメントと検証

`rule.md` とルールモーダルを実装挙動に揃える。Goのユニットテストと既存E2Eシナリオを新しい手番に対応させ、Composeのbackend/frontendサービス経由でテストとビルドを確認する。
