# 実装計画 - ロビーでのプレイヤー削除機能

ロビー画面において、ホスト（部屋の作成者）が参加しているプレイヤーを任意に選んで削除（キック）できる機能を実装します。

## ユーザーレビューが必要な項目
- ホストが自分自身を削除できないように制限します。
- 削除されたプレイヤーは自動的にトップ画面にリダイレクトされ、「ホストによって退出させられました」という通知を表示します。

## 変更内容

### [Backend] ゲームサーバーロジック
ホストからのキック要求を処理するロジックを追加します。

#### [MODIFY] [websocket.go](file:///home/yasuni/デスクトップ/makes/game-template/backend/handlers/websocket.go)
- `KickPayload` 構造体を追加（対象のプレイヤーIDを保持）。
- `processLogic` 関数内に `kick_player` メッセージのハンドリングを追加。
    - 送信者がホストであることを確認。
    - 対象がホスト自身でないことを確認。
    - 削除対象のプレイヤーを `state.Players` から除外。
    - 削除対象のプレイヤーのWebSocket接続に対して `kicked` メッセージを送信。
    - 最新の状態を全プレイヤーにブロードキャスト。

### [Frontend] 通信・状態管理
キック機能の通信処理と通知処理を追加します。

#### [MODIFY] [websocket.ts](file:///home/yasuni/デスクトップ/makes/game-template/frontend/src/websocket.ts)
- `socket.onmessage` 内で `kicked` メッセージを受信した際の処理を追加。
    - アラートを表示し、`handleReset()` を呼び出してトップ画面へ戻します。

### [Frontend] UI実装
ロビー画面にキックボタンを追加します。

#### [MODIFY] [App.tsx](file:///home/yasuni/デスクトップ/makes/game-template/frontend/src/App.tsx)
- `handleKick(targetId: string)` 関数を追加。`sendWs("kick_player", { targetId })` を呼び出します。
- ロビー画面のプレイヤーリスト（`For` ループ内）を修正。
    - 現在のプレイヤーがホストであり、かつリスト内のプレイヤーが自分自身でない場合に、削除ボタン（✕マークなど）を表示します。

## 検証計画

### 自動テスト
- 現時点では既存のテスト（`backend/handlers/websocket_test.go` など）を参考に、キック機能のユニットテストが追加可能か検討します。
- リモートCIでの実行を確認します。

### 手動確認
1. ブラウザを2つ開き、一方がホストとして部屋を作成、もう一方がプレイヤーとして参加します。
2. ホスト側の画面で、参加プレイヤーの横に削除ボタンが表示されていることを確認します。
3. ホスト側の画面で自分自身の横には削除ボタンが表示されていないことを確認します。
4. 削除ボタンをクリックし、プレイヤーがリストから消えることを確認します。
5. 削除されたプレイヤー側の画面で、アラートが表示されトップ画面に戻ることを確認します。
